# Tethys's Archive

คลัง Lore เกม Wuthering Waves ภาษาไทย โดย Ku-Bot Factory
เวอร์ชัน 2 — เขียนใหม่ด้วย **Vue 3 + Vite + Tailwind CSS v4**

---

## เริ่มใช้งาน

ต้องมี [Node.js](https://nodejs.org) 22 ขึ้นไปติดตั้งบนเครื่องก่อน

```bash
npm install       # ครั้งแรกครั้งเดียว
npm run dev       # เปิด dev server ที่ http://localhost:5173 (แก้ไฟล์แล้วเห็นผลทันที)
npm run build     # สร้างไฟล์จริงลงโฟลเดอร์ dist/
npm test          # ตรวจการบันทึกบทความและการแก้ไขฟอร์ม
npm run preview   # ลองเปิดผลลัพธ์ที่ build แล้ว
npm run check:glossary   # ตรวจอภิธานศัพท์ว่าตรงกับบทความ
npm run import:terms     # นำเข้าคำศัพท์จาก Archive ในเกม (data/wuwa_terms_th.csv)
```

## เปิดเซิร์ฟเวอร์จากเครื่องตัวเอง

ดับเบิลคลิก **`runserver.bat`** — จะ build แล้วเสิร์ฟที่พอร์ต **8220** ผูกกับทุก network interface
(`0.0.0.0`) เพื่อให้เข้าจากเครื่องอื่นและจาก forward port ได้

| เข้าจาก | ที่อยู่ |
| --- | --- |
| เครื่องนี้ | `http://localhost:8220/` |
| เครื่องอื่นในวง LAN | `http://<IP ในวง>:8220/` (สคริปต์พิมพ์ให้ตอนเปิด) |
| ภายนอก | `http://<WAN IP>:8220/` |

- ครั้งแรก Windows Firewall จะถามว่าจะอนุญาต Node.js ไหม ต้องกด **Allow** ไม่งั้นคนนอกเข้าไม่ได้
- ถ้าพอร์ต 8220 ไม่ว่าง สคริปต์จะ error ทันที (`strictPort`) แทนที่จะแอบย้ายไปพอร์ตอื่นเงียบๆ
- แก้ไฟล์แล้วต้องปิดแล้วเปิดใหม่ เพราะเสิร์ฟจาก `dist/` ที่ build ไว้ — ถ้าอยากได้ hot reload ใช้ `dev.bat` แทน
- เปลี่ยนพอร์ตได้ที่ `package.json` (script `serve`) และ `vite.config.js` (`preview.port`)

## อภิธานศัพท์ (popup คำเฉพาะ)

เอาเมาส์ชี้คำเฉพาะในเนื้อหา (หรือแตะบนมือถือ) แล้วจะเด้งคำอธิบายสั้นๆ ขึ้นมา
คีย์เวิร์ดมาจาก **3 ชั้น** ทำงานร่วมกัน

### ชั้นที่ 1 — อัตโนมัติจากบทความ (ไม่ต้องแก้อะไรเลย)

เขียนบทความใหม่ปุ๊บ ชื่อบทความกลายเป็นคีย์เวิร์ดทันที ทุกที่ในเว็บที่พูดถึงคำนั้นจะลิงก์มาหาเอง
คำอธิบายใน popup ใช้ **เรื่องย่อ** ของบทความนั้น

| ชื่อบทความ | คีย์เวิร์ดที่ได้ |
| --- | --- |
| `Threnodian` | Threnodian, Threnodians |
| `Suoming - 锁暝 \| ผู้ผนึกไว้ซึ่งสนธยา` | Suoming |
| `Rover ใช้ทุกพลังได้ยังไง?` | Rover |
| `เจาะลึก Suisui's EP \| ...` | ไม่มี (ขึ้นต้นด้วยภาษาไทย) |

ระบบจะเก็บคำอังกฤษที่อยู่หน้าสุดของชื่อบทความ และเติมรูปพหูพจน์ให้เอง
หมวดเนื้อเพลงข้ามทั้งหมด เพราะชื่อเพลงไม่ใช่ศัพท์เฉพาะ

**คุมเองได้ผ่านช่อง "คำที่ให้ลิงก์อัตโนมัติ" ในฟอร์มเพิ่มบทความ**

- เว้นว่าง → ให้ระบบเดาจากชื่อบทความ
- ใส่คำเอง เช่น `Ovathrax, Ovathrax's` → ใช้ตามที่ใส่ (จำเป็นเวลาชื่อบทความเป็นภาษาไทย)
- ใส่ `-` → ไม่ต้องลิงก์บทความนี้เลย

ในไฟล์ `articles.json` ช่องนี้คือ `"keywords": ["..."]` และ `"keywords": []` คือปิด

### ชั้นที่ 2 — เขียนเองใน `public/glossary.json`

ใช้เมื่ออยากได้คำอธิบายที่เขียนเฉพาะ (ไม่ใช่เรื่องย่อ) หรืออยากเพิ่มคำพ้อง
ถ้าคำซ้ำกับชั้นอัตโนมัติ **ชั้นนี้ชนะ** แต่คำพ้องจะถูกรวมจากทั้งสองฝั่ง

```jsonc
{
  "term": "Threnodian",              // คำหลัก ใช้เป็นหัวข้อใน popup
  "aliases": ["Threnodians"],        // คำพ้อง/รูปพหูพจน์/ชื่อภาษาจีน (ไม่ใส่ก็ได้)
  "short": "คำอธิบาย 1-2 บรรทัด",     // ข้อความใน popup
  "article": "threnodian",           // slug บทความที่คำอธิบายอ้างอิง
  "ownArticle": true                 // มีบทความของตัวเอง -> ไฮไลต์ในเนื้อหา
}
```

**`ownArticle` คือสวิตช์เปิด-ปิดการไฮไลต์** ระบบจะไฮไลต์เฉพาะคำที่มีบทความเป็นของตัวเองจริงๆ
คำอื่นยังเก็บไว้ในไฟล์เป็นข้อมูลอ้างอิง แต่ไม่ขึ้น popup เพราะปุ่ม "อ่านบทความเต็ม" จะพาไปคนละเรื่อง
(ยกเว้นคำที่ผูกกับ Archive ในเกมไว้ตามชั้นที่ 3 — คำพวกนั้นมีคำอธิบายของตัวเองแล้ว จึงไฮไลต์ได้โดยไม่ต้องมีบทความ)
เมื่อไหร่ที่เขียนบทความให้คำนั้นแล้ว ก็แค่แก้ `article` ให้ชี้บทความใหม่ แล้วเติม `"ownArticle": true`

**ที่มาของคำอธิบาย** — คำในชั้นนี้ย่อมาจากเนื้อหาที่เขียนไว้ใน `articles.json` เท่านั้น ช่อง `article` คือบทความที่คำอธิบายนั้นอ้างอิง
ส่วนคำที่คัดลอกมาจากในเกมตรงๆ อยู่ในชั้นที่ 3 และถูกทำเครื่องหมาย `"source": "game"` ไว้ให้แยกออกจากกันชัดเจน

ตรวจสอบได้ด้วย

```bash
npm run check:glossary
```

สคริปต์จะเช็คว่าทุกคำปรากฏในบทความจริง ลิงก์ชี้ไปบทความที่มีอยู่ และบอกคำที่โผล่บ่อยแต่ยังไม่มีในอภิธานศัพท์
ส่วนคำจากในเกม (ชั้นที่ 3) ใช้กติกาคนละชุด — ไม่บังคับว่าต้องมีในบทความ แต่ห้ามอ้าง `article` และสคริปต์จะบอกว่าตอนนี้มีกี่คำที่ถูกไฮไลต์จริง

กติกาการไฮไลต์

- คำเดียวกันไฮไลต์แค่ครั้งแรกของแต่ละย่อหน้า เพื่อไม่ให้เนื้อหารก
- คำที่ตรงกับชื่อบทความที่กำลังอ่านอยู่จะไม่ถูกไฮไลต์ (ไม่ลิงก์วนหาตัวเอง)
- คำภาษาอังกฤษต้องตรงทั้งคำ ไม่แมตช์กลางคำ
- ถ้ามีทั้ง `Lament` และ `The Lament` ระบบเลือกวลีที่ยาวกว่าก่อน

เพิ่มคำใหม่แค่แก้ `public/glossary.json` ไฟล์เดียว ไม่ต้องแตะโค้ด

### ชั้นที่ 3 — คำศัพท์จาก Archive ในเกม

คำอธิบายศัพท์ที่เกมแจกไว้ใน Archive (ฉบับแปลไทยทางการ) ถูกนำเข้ามาเก็บไว้ในไฟล์เดียวกัน
ต้นฉบับอยู่ที่ `data/wuwa_terms_th.csv` (คอลัมน์ `id, title, description, description_plain`) นำเข้าด้วย

```bash
npm run import:terms
```

หรือระบุไฟล์เอง `npm run import:terms -- path/to/file.csv`

สคริปต์รันซ้ำได้เรื่อยๆ ทุกครั้งจะลบคำ `"source": "game"` ชุดเดิมทิ้งแล้วใส่ชุดใหม่จาก CSV
**คำที่เขียนเองไม่ถูกแตะต้อง**

```jsonc
{
  "term": "โอเวอร์คล็อก",
  "text": "คำอธิบายเต็มจากในเกม",  // popup แสดงเต็มๆ ยาวเกินจอก็เลื่อนอ่านในกล่องได้
  "source": "game",             // ตัวแยกชั้น — ห้ามใส่ article หรือ ownArticle
  "sameAs": "Overclocking",     // ผูกกับคำที่เขียนเอง -> ยุบเป็น popup เดียว
  "gameId": [850073],           // id ในเกม เอาไว้ไล่ย้อนกลับไปหาต้นฉบับ
  "highlight": false            // ใส่เองได้ ถ้าคำไหนไปแมตช์กลางคำอื่นจนรก
}
```

คำที่ในเกมมีคำอธิบายมากกว่าหนึ่งอัน (คนละ `id` ชื่อเดียวกัน) จะถูกยุบเป็นคำเดียว เก็บข้อความไว้ทั้งหมดในช่อง `text` คั่นด้วยบรรทัดว่าง
popup แสดงข้อความเต็มเสมอ ไม่ตัดท้ายด้วย `…` — คำที่ยาวเกินพื้นที่บนจอ กล่องจะสูงเท่าที่ว่างจริงแล้วเลื่อนอ่านข้างในได้

**กติกาการไฮไลต์ของชั้นนี้ต่างจากสองชั้นแรก** — ไฮไลต์เฉพาะคำที่ปรากฏในบทความจริงเท่านั้น
คำที่เหลือยังอยู่ในไฟล์เป็นข้อมูลอ้างอิง พอเขียนบทความที่พูดถึงคำไหน คำนั้นจะเด้ง popup ขึ้นมาเอง ไม่ต้องไปแก้อะไร
popup ของคำกลุ่มนี้มีบรรทัดกำกับว่า *คำอธิบายจาก Archive ในเกม* เสมอ

#### ผูกคำไทยในเกมเข้ากับคำอังกฤษที่เขียนเอง

ในเกมเรียก `เอคโค่ / จินโจว / คลื่นทมิฬ` ส่วนบทความเขียน `Echo / Jinzhou / Dark Tide` — ถ้าปล่อยไว้ระบบจะมองเป็นคนละคำ
คำอธิบายทางการจากในเกมก็จะไม่ถูกหยิบมาใช้เลย จับคู่ไว้ที่ `data/term-links.json` ไฟล์เดียว

```jsonc
{
  "Echo": "เอคโค่",
  "Dark Tide": "คลื่นทมิฬ",
  "Tacet Field": ["สนามทาเซ็ต"]   // ใส่เป็น array ได้ถ้าในเกมมีหลายคำ
}
```

`npm run import:terms` จะเขียนช่อง `sameAs` ลงในคำฝั่งเกมให้ตามตารางนี้ แล้วเว็บจะยุบสองฝั่งเป็น popup เดียว

| เรื่อง | ผลลัพธ์ |
| --- | --- |
| คำอธิบายใน popup | ใช้ข้อความจาก Archive ในเกม (ทางการกว่า) |
| คำที่ hover ได้ | ทั้งคำอังกฤษและคำไทย รวมถึง alias เดิมทั้งหมด |
| ปุ่ม "อ่านบทความเต็ม" | ขึ้นเฉพาะคำที่ `ownArticle: true` เหมือนเดิม |
| การไฮไลต์ | คำที่ผูกแล้วไฮไลต์ได้ แม้จะยังไม่มีบทความของตัวเอง ตราบใดที่คำนั้นโผล่ในบทความ |

ตอนนี้ผูกไว้ 27 คู่ ถ้าเพิ่มคู่ใหม่แล้วชี้ไปคำที่ไม่มีอยู่จริง สคริปต์จะ error ทันที
คำในเกมที่ชื่อชนกับคำที่เขียนเองแต่ยังไม่ได้ผูก สคริปต์จะข้ามให้แล้วเตือนไว้ในผลลัพธ์

คำภาษาไทยที่สั้นกว่า 4 ตัวอักษรจะถูกปิดไฮไลต์อัตโนมัติ (`"highlight": false`) เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ
คำสั้นๆ อย่าง "ทีม" จะไปโดนกลางคำอื่นเช่น "เดิม**ทีม**ี"

ลำดับความสำคัญเวลาคำซ้ำกัน: **คำจากในเกม < คีย์เวิร์ดอัตโนมัติ < คำที่เขียนเอง**

### เพิ่มหมวดหมู่ใหม่

แก้ `src/data/categories.js` ที่เดียว — sidebar, dropdown มือถือ, ตัวเลือกในฟอร์ม และตัวนับ อัปเดตตามเอง

## สิ่งที่เปลี่ยนจากเวอร์ชัน 1

- แยกไฟล์เดียว 1,705 บรรทัด ออกเป็น component ย่อย
- **ลิงก์เจาะบทความได้** และปุ่ม back ของเบราว์เซอร์ใช้งานได้
- **ปิดช่อง XSS** — Vue escape ข้อความให้อัตโนมัติ ไม่มี `innerHTML` เหลืออยู่แล้ว
- ล็อกอินผู้ดูแลด้วย Supabase Auth และตรวจสิทธิ์ในฐานข้อมูล
- รูปปกใช้ path ในเว็บแทนการยิงไป `raw.githubusercontent.com` + โหลดแบบ lazy
- เพิ่มหน้า tag, บทความที่เกี่ยวข้อง, โครงกระดูกตอนโหลด, ค้นหาถึงเนื้อหาเต็ม
- ปิด modal ด้วย Esc, focus trap, รองรับ `prefers-reduced-motion`

## แนวทางพัฒนาต่อ

- รองรับ Markdown ในเนื้อหา (หัวข้อ ตัวหนา ลิงก์ข้ามบทความ)

- ซ่อนสปอยล์ตามเวอร์ชันเกม
- OG image ต่อบทความ (ต้องมี prerender หรือ serverless)
- แยก `content` ออกเป็นไฟล์ย่อย เมื่อบทความเกิน ~50 เรื่อง
